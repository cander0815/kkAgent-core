## P2：exit 后尚未轮询时返回已结束的 solo，界面误报成功

`resumeSolo` 直接复用数据库中 state=running 的记录，没有先确认它的 tmux 仍存在。用户刚 exit、轮询尚未收尾时点“继续沟通”，这个条件会命中。

随后 POST /api/solo 又调用 soloList。soloList 发现旧 tmux 已退出，将其 ended 并从列表移除，导致接口的 first 查询得到 nil。SoloModel.resume 对空结果仍返回 nil 错误值，也就是按成功处理；RootView 切到“会话”，但没有打开目标。

隔离实际复现：登记一个 running 但 tmux 已不存在的 solo，resumeSolo 返回旧 ID；立即执行接口相同的 soloList().first，结果为 nil，旧记录 ended。这是用户正常 exit 后点击继续的时序，不需要并发压力或异常注入。

最小修法：仅对命中的 running 记录先检查/收尾其已退出状态；starting 仍复用，不因没有 tmux 判结束。已退出则按原 sessionId 的续接流程新建 solo，不返回过期项。界面/API 不得将没有目标记录的结果当成功。无需新加状态表或外部终端监控。

回归：exit 后不等轮询立即继续，有历史文件时一次操作返回新的 solo 并选中；真正 running 和 starting 的重复点击仍复用；failed 仍要求先销毁。

### 已证实的问题

2. **P2：正看终端时仍发授权通知。** `AttentionNotifier.update` 没有查询 SoloViewTracker，而 updateSolos 只对结果通知查询；因此用户在会话页前台正看这个 solo 的授权框时照样提交横幅，与方案“正看着时不发”不符。对有 soloId 的授权等待用相同可见性判定抑制；不要写结果的已读。建议离开终端后仍未处理的等待可再通知，行为需明确。无需扩展到检测普通群成员终端。

## 需要落实的设计细节

1. **Claude 结束判断用 mainTurn，不用合成后的 state。** 当前 Entry.state 会被主/子 agent 的授权等待覆盖。应在已接受、属于主 agent、promptId 校验通过的 Stop / StopFailure 分支，捕获 mainTurn 的 working → idle 转换，在锁外回调。这样主回合结束而子 agent 仍等授权时，结果照记，activity 仍为 waitingPermission；重复 Stop 不重复记。不要把 onIdle 当结束事件。拒绝授权和 markTurnEnded 的 interrupted 也只在实际成功转换时记一次。

2. **Codex 要有序、可靠地消费结束事实。** 当前 turnSnapshot.ended 是字典，不含结束时间或顺序；同一轮询间隔结束多轮时，不能靠字典遍历决定 lastOutcome。最小改法是向检查方暴露已有 endedOrder 所对应的有序结果，带日志结束时间，依次消费并以最后一条为最近结果。基线只在首次可信 snapshot 成功后建立；nil 不得当空集合。核心重启首个可信快照只建基线，不补报，接受其离线漏提醒的既定边界。换段同样不能把新段带来的旧结束记录直接认成刚完成，需结合日志时间/首次已知基线划清范围。不必新增事件表。

3. **已读是终端实际可见，不只是 App active 和 selectedId。** 至少要求对应主窗口可见、未最小化、当前会话页且所选 solo 的 running 终端确实挂载显示；关窗口后 App 仍在菜单栏，不能把新结果记已读。读取并标记当前展示数据中的 lastEndedAt，不能稍后拿更新后的值把用户尚未看到的另一轮一并消费。授权通知的抑制和结果已读分开，不要因看过结束结果就消费授权等待。

4. **把通知基线、命名空间及绑定切换规则写清。** 首次成功取得 solo 列表时仅对已有结束结果建通知基线；接口失败不建立空基线，不把旧结果标已读。已有授权等待和启动失败仍需提醒（它们正需要人处理）。通知键加事件类型与 owner 命名空间，如 result|solo|id|endedAt、permission|solo|id|since、startup|solo|id；solo 无论是否绑定群，授权等待以 solo 身份去重，仅点击目标按当前归属选择，避免同一次等待因绑定/解绑重复通知。沿用现有提交成功才去重和失败重试。

5. **人工 Esc 兜底复用已经验收的取证规则。** 不能另写一个仅凭尾部通用打断字符串的宽松分支；必须核对当前 launch / promptId / revision、主线当前回合的精确打断证据及结束屏幕，成功 markTurnEnded 才写 interrupted。新的提示词或忙碌画面均不能用旧打断标记收尾。绑定群和未绑定 solo 共用同一状态转换，不重复记结果。

## 范围和界面

- 同意 UserDefaults 保存已读、不加核心已读接口/事件表、不做提问分类或结果区。Codex 人工审批首版不支持可以接受，但文案应写“暂不检测人工审批”，不能保证自动审查永远不会需要用户处理。
- 正常 Stop 只能证明本轮结束，不能证明任务做对。通知建议用“这一轮已结束”，避免“做完了”被理解成任务验收成功。StopFailure 可写“这一轮出错了”。
- 未读规则应显式限定 completed / failed，interrupted 不亮红点；working + 旧结果未读要同时显示。
- 全局和页面各自轮询可以先保留；全局通知只由一个协调器消费，旧请求不得覆盖更新数据。此轮不要求额外缓存体系或事件总线。

## 最小验收补充

在原方案清单外，覆盖：主回合结束而子 agent 仍等授权；重复及旧 promptId 的 Stop；一次检查间隔内正常结束后又被打断（最近结果顺序正确）；首次 snapshot 读不了后恢复及换段不补报历史；App active 但主窗口关闭/最小化不标已读；已有授权等待在 App 重启后仍提醒、同一等待绑定/解绑不重复；旧打断标记后新回合已开工不误收尾。允许对难触发的 StopFailure 用隔离事件注入验证，真机未覆盖需如实注明。

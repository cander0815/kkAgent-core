# 单独会话：这一轮怎么结束的、未读结果、需要人处理的提醒

日期：2026-11-13
来源：kkAgent-参考OpenMausBot优化建议书.md 里值得借鉴的第 1 到 3 点（KK 确认先做这三点），按「能少则少」重新收窄了范围。
状态：方案，待 pm 评审。评审通过后只在测试核心 7799 上开发和验证，替换正式环境等 KK 说。

## 一 要解决什么

KK 同时开好几个单独会话（左边栏「会话」），交代完事情就切去做别的。现在：

- 哪个会话这一轮做完了，只能挨个点开终端看；
- 没拉进群的单独会话卡在授权框上，不会有任何提醒（`/api/attention` 把它过滤掉了，`main.swift` 的 onPermission 也只通知群里的成员）；
- Claude 的 Stop 和 StopFailure 都只记成「空闲」，看不出是正常结束还是出错了。

做完以后：

1. 列表每一行能看到「执行中 / 本轮已结束 / 失败 / 被打断 / 需要授权 / 启动失败」；
2. 本轮结束后没看过的会话有一个小红点，看过就消失；
3. 结束、失败、需要授权、启动失败发系统通知，点通知跳到这个会话的终端。

不做：任务记录、消息意图、改用 app-server、判断「回复里是不是在问你问题」、Codex 的人工审批检测（理由见第六节）。

## 二 四种事实分开

| 事实 | 取值 | 存在哪 |
| --- | --- | --- |
| 会话生命周期（已有） | starting / running / failed / ended | solo_sessions.state，不改含义 |
| 现在在干什么 | working / waitingPermission / idle / unknown | 内存，Claude 用已有的 AgentStatusStore；Codex 用已有的 CodexTurns |
| 最近一轮怎么结束的 | completed / failed / interrupted | solo_sessions 新增两列：last_outcome、last_ended_at |
| 用户看过没有 | 看过的那一轮的 last_ended_at | App 本机 UserDefaults（`soloViewed.<soloId>`） |

「未读」= last_ended_at 不为空，且和 App 记下的「看过的那个时间」不一样。结束时间每轮都不同，所以：连续结束两轮只算一个未读，看过后又结束一轮会重新亮。

已读状态放 App 而不放核心：它只是界面上的显示，只有一个用户、一台机器，不用为它加接口和表字段。

## 三 结束检测

### 3.1 Claude（单独会话都在虚拟机里，已经装了状态 hook）

在 `AgentStatusStore.record` 里，**只有主 agent 的回合从 working 变成 idle** 时才算「一轮结束」：

- Stop → completed；StopFailure → failed；
- 新增回调 `onTurnEnded(owner, outcome)`，在锁外调用。原来的 onIdle 不动（它还负责唤醒投递，授权解除、核心重启恢复也会触发它，不能当成「做完了」）。

不会误报：

- 新建、继续沟通打开后，界面就绪时 `markReadyAfterLaunch` 记成空闲：它不是从 working 变过来的，不触发；
- 迟到的、prompt_id 对不上的 Stop 本来就被忽略；
- SubagentStop 不触发（只是子 agent 结束）；
- 主 agent 结束但子 agent 还有授权在等：状态是 waitingPermission，按「需要授权」提醒，同时照样记下这一轮的结果。

**被打断**：
- 用户在终端里按 Esc 打断时 Claude 不发 Stop（开发时先实测确认）。目前状态会一直停在 working，列表会一直显示「执行中」；
- 补法：定时检查（已有的 3 秒轮询）里，对状态是 working 的单独会话，每 10 秒看一眼屏幕。用已有的 `MemberReadiness.claudeScreen`：认出输入框已经空闲、没有「esc to interrupt」时，再读一次会话记录尾部；确认最后是打断标记，就调用已有的 `markTurnEnded` 收尾，记 interrupted；
- 打断是用户自己按的，**不发通知**，只改列表状态；
- 拒绝授权导致的结束（`state(of:)` 里 endedByInterrupt 那条）同样记 interrupted。

### 3.2 Codex（物理机，tmux，`--approve-for-me`）

复用 `CodexTurns`。它已经按 turn_id 记了每一轮怎么结束的（complete / aborted:原因）：

- 定时检查里对运行中的 Codex 单独会话调用 `turnSnapshot`，看 endedTurns 里有没有**新出现的** turn_id；
- task_complete → completed；turn_aborted → interrupted（不发通知）。

**基线**：单独会话变成 running 的那一刻，把当时已有的 endedTurns 全部记为「已知」，只认之后新出现的。这样：
- 新建时为拿会话 ID 跑的「已就位」那一轮，在 codex exec 里，tmux 启动前就结束了，被基线吃掉；
- 继续沟通打开的旧会话，历史里的轮次也被基线吃掉；
- 核心重启后同样先建基线，不补发。代价是：核心停着的那段时间里结束的一轮，不会提醒。

基线只放内存（`[soloId: Set<turn_id>]`），endedTurns 只留最近 50 个，正常使用够用。

### 3.3 记结果

两种引擎最后都走同一个函数 `recordSoloTurn(soloId, outcome)`：
- 更新 solo_sessions 的 last_outcome、last_ended_at；
- 写一行日志。

拉进群的单独会话照样记（同一份状态，只记一次）。群成员（非单独会话）不做这件事，群那边已经有自己的消息流。

## 四 需要授权：补上没进群的单独会话

1. **`/api/attention` 返回没绑群的单独会话**：
   - `AttentionItem` 加 `soloId`（默认 0，旧 App 解码不受影响）；
   - 没绑群的 solo 返回 soloId，groupId、memberId 为空或 0，alias 用「单独会话 #id」（App 再换成显示名）；
   - 绑了群的照旧按群成员返回，不重复。
2. **拒绝授权后能解除**：`refreshWaiting` 现在对没绑群的 solo 直接跳过，拒绝后要等下一个 hook 才解除。
   - 把 `state(of member:)` 里读会话记录核对的那段，改成接收 `(owner, sessionId, vm, tmux, label)`；
   - Member 和 SoloRecord 各自传参调用，不给 solo 假造成员。
3. **main.swift 的 onPermission**：没绑群的 solo 不需要通知群主，保持现状。用户这边的提醒由 App 通过 attention 发。

## 五 App

### 5.1 数据

- `SoloSession` 加：
  - `activity`：working / waitingPermission / idle / unknown，Claude 读 AgentStatusStore 内存状态，Codex 读 CodexTurns 缓存；
  - `lastOutcome`、`lastEndedAt`。
- `AppModel` 的全局 2 秒刷新里，加一次 `GET /api/solo`，交给通知协调器。
  - 现在只有「会话」页打开时才刷新这个列表，切到群聊页就收不到；
  - `soloList` 本身很轻：每个会话一次 `tmux has-session`，会话名有 15 秒缓存；
  - 「会话」页自己的刷新循环保留不动。

### 5.2 列表

每行的右边显示一个状态标签：

| 情况 | 显示 |
| --- | --- |
| 生命周期 starting / failed | 正在启动 / 启动失败（已有） |
| waitingPermission | 需要授权（醒目色） |
| working | 执行中 |
| idle 且有未读 | 本轮已结束 + 小红点；失败显示「失败」+ 红点 |
| idle 且已读 | 不显示（或显示最近结束时间，淡色） |
| interrupted | 已打断（淡色，不算未读） |

一个会话可以同时是「执行中」和「有未读」：上一轮没看就又开始了新一轮，红点保留。

### 5.3 什么算「看过」

满足以下全部条件时，把这个会话当前的 last_ended_at 记为看过：
- App 在前台；
- 当前是「会话」页；
- 选中的就是它，右边终端正在显示。

如果新一轮结束时正好满足这三个条件，直接记为看过，也不发通知（用户正看着）。

### 5.4 通知

扩展现有的 `AttentionNotifier`，不另写一套：

| 事件 | 标题 | 去重键 |
| --- | --- | --- |
| 本轮已结束 | 「<会话名> 这一轮做完了」 | soloId + last_ended_at |
| 本轮失败 | 「<会话名> 这一轮出错了」 | 同上 |
| 需要授权（没绑群的 solo） | 「<会话名> 在等授权」+ 工具和命令 | soloId + since |
| 启动失败 | 「<会话名> 启动失败」+ 原因 | soloId + "failed" |

- 正文：目录简称、Claude / Codex；
- 已经看过的（第 5.3 节）不发；被打断的不发；
- 点通知：打开主窗口，切到「会话」页，选中这个 soloId。现在 onOpen 只认群 + 成员，要加一个按 soloId 跳转的分支，RootView 负责切模块；
- 不自动切页、不抢焦点，只有点了才跳；
- App 第一次拿到列表时，已经存在的结束结果只建基线，不补发（不然重启 App 会把每个会话都通知一遍）。

## 六 不做的和原因

- **Codex 的人工审批**：单独会话的 Codex 用 `--approve-for-me`，交给 Codex 自动审查，基本不会停下来等人。没有可靠的信号，不靠屏幕关键词去猜。
- **「它在问你问题」**：回复最后在提问，也只算「本轮已结束」，用户点开就看得到。不加模型分类。
- **单独的「查看本轮结果」区域**：点开就是它的终端，结果就在那里。会话已经退出的，用会话浏览看历史（已有）。
- **核心记已读、事件表、增量事件接口**：只有一个用户、一台机器，App 记已读就够了。

## 八 验证（测试核心 7799，真机跑）

1. 新建 Claude，不输入：没有「本轮已结束」，没有通知。
2. Claude 交代一件事，正常 Stop：列表变「本轮已结束」+ 红点，通知一次；重复刷新不重复通知；选中后红点消失。
3. 停在会话页、选中它、App 在前台时结束：不发通知、不亮红点。
4. Claude 中途按 Esc：几秒到十几秒内列表回到「已打断」，不发通知。
5. Claude 授权：没绑群时有「在等授权」通知，点通知跳到这个会话；在终端里拒绝后，状态能自己解除。
6. StopFailure：能在测试会话里触发就实测一次（不动 KK 的网络和正式环境），列表显示失败；触发不了的，在评审记录里如实写「未实测」。
7. 新建 Codex：「已就位」那一轮不提醒；交代一件事做完后提醒一次；Esc 打断显示已打断。
8. 继续沟通打开一个旧会话：历史轮次不提醒。
9. 重启测试核心、重启 App：不补发旧通知；last_outcome 还在。
10. 拉进群的单独会话等授权：只有群那条通知，不重复。
11. 启动失败（比如关掉虚拟机再新建 Claude）：有一条启动失败通知。

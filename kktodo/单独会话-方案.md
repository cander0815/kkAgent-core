# 左边栏「会话」：脱离群聊、直接选路径新建的单独会话（KK 提，2026-11-13）

## KK 定的

1. 左边栏新加一项「会话」。里面「新建会话」：**第一步选工作路径**，再选 Claude / Codex，新建一个不属于任何群的会话。
2. 会话一直在后台运行（tmux 托管）。只有两种情况会结束：点「销毁」（关掉它的 tmux）；在终端里主动 exit。
3. 列表**只显示在这里创建、并且还在运行的会话**。exit 之后自动从列表去掉；销毁后也去掉。
   会话记录文件不删，在上面原有的「Claude 会话 / Codex 会话」浏览页里还能看到它的历史。
4. 第一版就支持把它拉进群聊。

## 要动核心（和界面一起改）

核心已经有「群里新建会话」那套 tmux 托管：Claude 进虚拟机、首次信任目录、等界面就绪、Codex bootstrap、目录校验。
单独会话复用这一套，只是不挂在群上。放进核心，而不是界面自己起 tmux，原因有两个：
- 启动逻辑只有一份；
- 拉进群时核心知道它是自己托管的，复用同一个 tmux 进程，不会出现同一个会话两个进程。

### 数据

新表 `standalone_sessions`：
- id、agent、vm、session_id（Codex 建好前为空）、cwd、tmux（`kk-solo-<id>`）、launch_id（Claude 的 hook 令牌）、created_at。

### 接口

| 接口 | 作用 |
|---|---|
| `GET /api/solo` | 列出还在运行的单独会话。列的时候顺手清理：tmux 已经不在（用户 exit 了）的记录直接删掉，所以 exit 后自动从列表消失 |
| `POST /api/solo` `{agent, cwd}` | 新建。校验和「群里新建会话」相同：目录存在并且是目录；Claude 要在 /Users 下、正好一台 VM 在运行 |
| `DELETE /api/solo/:id` | 销毁：关掉 tmux、删记录。如果它正绑在某个群里，那个成员一起解除（群里显示它已退出，可移出） |

### 启动

- **Claude**：预生成 UUID，`claude --session-id <id>` 在 tmux 里启动（虚拟机里经 `ubx shell`），同样装状态 hook。
  hook 现在按成员 id 上报（`/api/members/:id/hook`），单独会话还不是成员，所以改成按「托管会话」上报：
  AgentStatusStore 的键从成员 id 扩展成「成员或单独会话」。拉进群后，群成员直接用这份状态。
  这样单独会话拉进群后，忙闲判断、紧急消息打断都照常可用。
- **Codex**：会话 ID 要第一轮跑起来才有。新建时先用 `codex exec` 跑一轮最小的开场（「已就位，等待指示」那种，立即结束），回填 ID，再在 tmux 里 `resume`。
  界面上显示「正在启动」，失败显示原因。
- 启动在后台做，新建接口马上返回；列表里先显示「正在启动」。

### 界面

- 左边栏加「会话」，和群聊、会话浏览并列。
- 列表每行：类型图标、目录（短路径）、创建时间、状态（正在启动 / 运行中 / 启动失败）。
  选中后右边是内嵌终端（复用成员详情里的 SwiftTerm 终端，接入它的 tmux），可以直接交互。
- 顶部「新建会话」：弹窗**第一项是工作目录**（输入框 + 选择文件夹，默认填上次用的目录），再选类型。
- 每行有「销毁」按钮，点了要二次确认（「关闭这个会话的进程，会话记录保留，可以在会话浏览里看历史」）。

### 拉进群

- 群里「添加成员」的「拉入已有会话」，旁边加一个下拉，列出还在运行的单独会话，选一个就填好（也可以照旧手填会话 ID）。
- 核心发现这个会话 ID 是单独托管会话：成员设成 `headless`，`tmux` 用它现有的 tmux 名，不另起进程；入群说明直接贴进它的 tmux。
- **进程归属以「会话」页为准**：
  - 从群里移出成员、或者解散群，只解除绑定，**不关它的 tmux**，它仍在「会话」页里；
  - 只有「销毁」或用户 exit 才结束进程。
- 同一时间只能绑一个群（沿用托管会话不能跨群的规则）。
- 已经绑在群里的单独会话，列表里标出「在群 X 里」。

### 不做的（第一版）

- 只支持普通群（集群群聊的原因同前：群主会被复制进子群）。
- 不新建到物理机上的 Claude（规则同集群）。
- 不给单独会话发消息的入口：它不在群里，要说话就打开终端直接打字。

## 验证（测试核心 7799）

1. 新建 Claude / Codex 单独会话：列表出现，状态从「正在启动」到「运行中」；打开终端能交互。
2. 在终端里 exit：刷新后自动从列表去掉，会话浏览页里还能看到历史。
3. 销毁：tmux 和进程退出，列表去掉，会话记录还在。
4. 核心重启：单独会话不受影响，列表照常显示（tmux 本来就不依赖核心）。
5. 拉进普通群：不另起进程（核对进程数），入群说明送达，群消息能送进去、它能回复；紧急消息能打断它（hook 状态共用）。
6. 从群里移出、解散群：tmux 还在，会话页里还在；再销毁才结束。
7. 绑在群里时销毁：群里的成员显示已退出。
8. 拒绝：目录不对、不在 /Users 下（Claude）、没有或有多台 VM、集群群聊里拉入、同一个会话拉进第二个群。

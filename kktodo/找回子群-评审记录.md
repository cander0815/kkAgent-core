## 已证实：Codex 分段文件的候选 ID 不正确

现有 Sessions.listCodexLocal 通过文件名最后 36 字符取会话 ID。对于项目已实际出现过的 `rollout-…-<sessionId>_<分段ID>.jsonl` 格式，会得到错误 ID，而不是 session_meta.id。

隔离建立原文件与更新的分段文件，二者 session_meta.id 相同、cwd 都是同一 worktree。实际 Sessions.list 返回两个不同候选，较新候选的 ID 含 `_part1`，不等于原 ID。按方案取最新就会拿错 tester ID，后续 resume 无法保证落到原会话。

要求：reopen 使用的候选身份取可信 session_meta.id，按真实 ID 合并分段后再比较最近时间，不能把分段当成另一个会话。可修复公共 Sessions 解析，也可在 reopen 候选解析处处理，不要求借机重构会话浏览。

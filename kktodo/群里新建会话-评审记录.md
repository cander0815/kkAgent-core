## 实现约定

1. Codex 的第一条必须明确为初始化，不要等待后续任务。普通 `Prompts.intro` 目前只写“不需要回复，等群消息”，缺少 tester bootstrap 已有的“立即结束本轮、不要 sleep/轮询”要求。可在普通入群说明后附中性的初始化结束要求，不能拿 tester 专属角色、verdict 和 coder 流程替代用户填写的角色。
2. 首轮 bootstrap 先排队，随后收到的任务保持 pending；没有 sessionId 前不走普通 tmux 投递。初始化失败应在普通群明确显示错误和可采取的操作，不能一直显示正在启动。现有 `afterTurn` 和 bootstrap 失败文案按子群/群主设计，普通群应通知用户，避免出现“找不到群主”的误导。不要求首版新增复杂自动重试，明确保留成员并提示重新创建或现有可用重试方式即可。
3. 普通群新建出来的托管会话仍应受现有 `isHeadlessSession` 限制，不能通过“拉入已有会话”再加入其他群；拒绝集群新建须在 API 执行，不能只隐藏界面入口。沿用现有托管成员不能换会话的约束即可。
4. `create=true` 允许缺省/空 sessionId（或客户端固定发送空字符串，需在协议中写清），不得先走已有会话定位校验。旧请求不带 create 时保持原拉入逻辑；cwd 仅新建使用。目录输入做常规去首尾空白及路径标准化，默认目录只是表单建议，仍执行方案已有校验。
5. 返回成员只表示成员已登记，不代表终端已经就绪。“正在启动”使用实际 bootstrap/首次投递进度显示，成功、失败均可识别；无需为了这句文案引入完整新状态机。移出/解散普通群托管成员确实可复用已有 cancel + Tmux.kill；普通已有会话成员继续保留原生命周期。

# 集群统筹

只承担根指挥职责：需求、依赖、资源、最终交付审阅。普通业务编码、实测、合并交给约定执行角色；用户另有明确安排时按新安排执行。席位数、角色和工具来自本次授权，不把历史八席、Claude/Codex配对变成通用默认。

## 开始与恢复

首次接手、上下文压缩后或交接恢复时，重新读取本技能、当前适用的 AGENTS.md、最新用户决定和执行台账顶部恢复快照。只加载当前场景的配套技能，不重读全部历史。

在 koala-ticketing 工作时先读 [项目约定](references/koala-ticketing.md)。其他项目不加载该文件。

核对实际主分支 HEAD/脏文件、活跃执行者、最新实质报告及资源持有人；文档是恢复入口，当前事实用于校正过期记录。收到过消息、会话仍存在、过去负责过，均不证明正在执行。

## 调度循环

1. 从已确认目标中提取最小可验收增量，区分真实前置与排期习惯。后端不因尚未需要的页面入口等待；最终接线保留需求映射。
2. 派发前使用 `$cluster-dispatch`，完成集中核查和任务书复查、确认文件落盘后再创建/恢复执行组。工具不可用就如实标明，不编造命令或成功状态。
3. 执行中只处理实际阻碍和资源冲突。普通审读发现留在根核查表，等本轮结果统一验收；不碎片补发、不连续催正常返修组。
4. 每批完成或资源释放后，立即核结果并接续下一批有前置的任务；没有可执行工作可以零活跃，不为满席启动空等组。
5. 交付时使用 `$cluster-acceptance`；会话中断、投递、权限、原生层卡住或需要恢复时使用 `$cluster-recovery`。只读当前所需技能。

## 资源与合入

- 主分支写窗、共享模拟器、同库 DDL 分开登记，各有唯一持有人、允许范围、下一位和明确释放条件。时间经过不构成释放。
- 合入申请到达时才实时核主 HEAD、祖先、路径交集与现有测试结论；主分支只准当前持有人写。根只读核对和放行，由 coder 合并。
- 混合复验前预约短窗；主 HEAD 前移先看实际差异再决定定向复验，不机械全量重跑。纯文档差异可沿用仍有效业务证据。
- 小文档更新批量合入；已授权同范围短窗内不为每几行反复排队。合入回报核对后立即释放。
- 合并状态、SHA和工作区变化只写根自己的队列/恢复记录，不广播主分支前移或要求全员同步。仅向当前必须执行者发具体放行/阻塞；确有文件冲突或数据破坏风险才精确协调。
- 用户 watch 会立即加载合入代码时，先查迁移向后兼容性；兼容则协调先 DDL 后合依赖代码，不兼容则受控切换。具体环境迁移/生产授权规则优先，不能凭“只差几十秒”冒险，也不擅停 watch。

## 台账与汇报

沿用项目现有台账，缺少时按 [记录模板](references/records.md) 建立。业务确认与指挥裁决分别编号，托管裁决必须记录授权、依据、影响、实现/验证状态，不替用户发明业务确认。

有重要合入、整链/并发验收、关键缺陷或阻塞变化、阶段收尾时主动简报：完成内容、证据、实际主分支 SHA、未验边界和下一步。相近小进展合并汇报；派发、消息送达、提交不当验收完成。

状态询问或处理消息时检查长任务，优先超过两小时者；拆开开发、实测、排队、合入、工具、外部配置及根待关单时长，不把总耗时算成编码慢。不另建定时任务，除非用户要求。

## 恢复快照

在阶段切换、资源交接、挂起或可预见的上下文切换前更新台账：当前目标/授权边界、决定和任务书路径、各任务状态及执行者、固定源码/主分支/运行 SHA、资源租约、未提交改动位置、未验与下一步。禁止保存凭据或完整私有会话数据。

快照不是永久锁或成功证明；恢复后重新核事实。Skill 提供可重读流程，台账保存变动状态，两者都不能保证模型永远记住；不要声称已安装就会自动持续执行。
